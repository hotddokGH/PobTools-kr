# PobTools PoE1 전체 한국어화 설계

## 상태

- 사용자 승인: 2026-09-01
- 대상 프로그램: PobTools v1.1.0
- 대상 게임: PoE1만
- 배포 형태: 공개 배포 가능한 한국어판
- 공식 용어 기준: 로컬 공식 한국어 클라이언트 패치 3.29.3.2

## 목표

현재 `PobTools-ko-test`의 공식 용어 적용 미리보기를 실제 사용자 화면 기준의 전체 한국어판으로 완성한다. 프로그램 내부의 영문 식별자, 빌드 저장 데이터, 거래 API 값과 계산 로직은 원문을 유지하고, 화면에 표시되는 실행기·PoB UI·아이템·젬·패시브·몬스터·능력치 설명은 한국어로 표시한다.

이번 작업은 유지보수 가능한 소스 기반 한국어판을 만든다. 원본 배포 폴더 `PobTools-1.1.0`은 수정하지 않는다.

## 완료의 의미

`전체 한국어화`는 다음 조건을 모두 만족하는 상태다.

1. 실행기 기준 키 109개가 모두 한국어로 표시된다.
2. 현재 PoE1에서 접근 가능한 PoB 화면, 팝업, 도움말, 드롭다운, 표 머리글, 계산 설명과 툴팁에 의도하지 않은 영어 또는 중국어가 남지 않는다.
3. 아이템·젬·패시브·몬스터·고유 아이템·능력치·옵션 명칭은 공식 한국어 클라이언트 데이터와 일치한다.
4. 동적으로 숫자나 이름을 끼워 넣는 문구는 공식 한국어 서식과 조사·어순을 보존한다.
5. `Path of Building`, `PoB`, `DPS`, 파일명, URL, 키보드 키처럼 번역하지 않는 값은 이유가 기록된 허용 목록에만 존재한다.
6. 현재 코드에서 도달하지 않는 구버전·내부 키는 기계 번역으로 채우지 않는다. 기준 사전과 키 구조는 맞추되, 화면 도달성 보고서에서 제외 이유를 기록한다.
7. 번역 누락, 중국어 잔여, 서식 토큰 손상, 공식 명칭 불일치가 자동 검사에서 0건이다.
8. 소스 빌드, 글꼴 검사, 주요 화면 실행 검사와 공개 ZIP 내용 검사가 모두 통과한다.

## 범위

### 포함

- `Data/launcher/ko-KR`: 실행기 UI 전체
- `Data/poe1/ko-KR`: `tags`, `items`, `gems`, `ui`, `stats`, `passives`, `uniques`, `monsters`
- 실행기와 업데이트 상태에 하드코딩된 중국어·영어 문구
- PoB 화면에서 번역 계층을 우회하는 표시 문자열
- 한국어 검색과 입력이 기존 PobTools 동작을 유지하는지에 대한 회귀 검사
- Noto Sans KR과 OFL 라이선스를 포함하는 공개 배포물
- 미번역 탐지 보고서와 공식 용어 출처 보고서

### 제외

- PoE2 번역
- 사용자가 실행하는 범용 번역 생성기 제품
- GitHub 저장소 생성, 릴리스 업로드와 서명키 운영
- Path of Building 계산 로직 자체의 기능 변경
- 내부 영문 식별자, 저장 파일 형식, 거래 API 요청값의 현지화

공개 자동 업데이트 채널은 한국어 배포 저장소와 서명키가 정해지기 전까지 활성화하지 않는다. 개발 및 시험 배포본은 `UpdateTranslations=0`을 유지해 중국어 데이터 팩이 한국어 작업물을 덮어쓰지 않게 한다.

## 작업 공간

- 보존 원본: `PobTools-1.1.0`
- 현재 데이터·실행 검증본: `PobTools-ko-test`
- 영구 소스 작업본: `PobTools-ko-source`
- 최종 산출물: 소스 작업본의 `dist` 아래 버전 명시 ZIP

`PobTools-ko-source`는 `Hsiung-Shao/PobTools-zh`의 v1.1.0 소스를 기준으로 만든다. 현재 폴더들은 Git 저장소가 아니므로, 소스 작업본만 Git 이력을 가진 유지보수 기준점으로 사용한다.

## 번역 데이터 계층

한국어 값은 다음 우선순위로 결정한다. 높은 계층과 충돌하는 낮은 계층 값은 자동 적용하지 않는다.

1. **현재 공식 데이터의 정확한 ID 결합**
   - 영어와 한국어 행을 같은 표의 안정 ID로 결합한다.
   - 현재 확보한 `BaseItemTypes`, `ActiveSkills`, `PassiveSkills`, `MonsterVarieties`, `ClientStrings`, `ClientStrings2`, 능력치 설명, 고유 아이템과 모드 이름 보고서를 사용한다.
2. **현재 공식 데이터의 구조화 서식 결합**
   - 숫자, 범위, 개행, 색상 태그와 조건부 조각을 자리표시자로 정규화한다.
   - 같은 stat ID 집합, 조건, 핸들러와 서식 구조가 일치할 때만 공식 한국어 템플릿을 적용한다.
3. **PoB 전용 UI 번역**
   - 공식 게임 데이터에 없는 버튼, 계산 설명, 설정과 도움말을 문맥에 맞게 직접 번역한다.
   - MIT 라이선스의 `antonio-kim-77/PathOfBuilding-kor` 커밋 `4b4129ef80818f38a221e51ac4cee17cb680b94b`는 PoB 전용 UI의 참고 자료로만 사용한다.
   - 해당 포크의 게임 용어는 현재 패치의 공식 데이터로 다시 덮어쓰며 그대로 신뢰하지 않는다.
4. **검수된 수동 예외**
   - 자동 결합이 불가능하지만 화면에 도달하는 항목만 영어 원문, 한국어 값, 문맥, 검수 이유를 구조화 파일에 기록한다.
5. **의도적 원문 유지 허용 목록**
   - 제품명, 약어, 파일명, URL과 키 표기만 허용한다. 각 항목에 이유가 없으면 검사 실패다.

중국어 사전 값은 키 목록과 런타임 범위를 확인하는 용도로만 사용한다. 한국어 번역의 원문이나 번역 근거로 사용하지 않는다.

## 구성 요소

### 1. 공식 용어 결합기 확장

기존 `tools/official-terms`의 표별 보고서를 입력으로 삼아 자리표시자 정규화와 우선순위 병합을 수행한다. 결과는 사전별로 결정적이어야 하며 같은 입력에서 바이트 단위로 같은 JSON을 생성해야 한다.

출력마다 다음 출처 메타데이터를 보존한다.

- 공식 패치
- 표 또는 RePoE 파일
- 안정 ID 또는 구조 식별자
- 영문 원문
- 공식 한국어
- 적용 계층
- 충돌 또는 제외 이유

### 2. 도달 가능 UI 폐쇄 검사

현재 PoB 소스와 기준 사전에서 표시 후보를 수집해 다음 네 집합으로 분류한다.

- 공식 용어로 해결됨
- PoB 전용 수동 UI로 해결됨
- 의도적 원문 유지
- 미해결

미해결 항목이 하나라도 있으면 공개 배포 검사는 실패한다. 구버전·내부 키 제외는 파일명, 소스 위치와 제외 사유가 있는 명시적 목록으로만 허용한다.

### 3. 소스 기반 하드코딩 문구 처리

JSON 번역 계층에 들어오지 않는 실행기 제목, 링크, 업데이트 상태와 오류 메시지를 한국어로 바꾼다. 범용 다국어 프레임워크를 새로 만들지 않고 한국어 배포판에 필요한 표시 경계만 수정한다.

프로그램 버전, 업데이트 자산 검증, 계산 로직과 내부 영문 데이터는 건드리지 않는다.

### 4. 런타임 누락 수집

`translate_misses.log`를 주요 화면 시나리오마다 초기화해 새 누락만 수집한다. 시나리오는 최소한 다음을 포함한다.

- 실행기와 설정
- 새 빌드 및 빌드 가져오기/내보내기
- 패시브 트리와 검색
- 스킬과 젬 선택
- 아이템 편집·검색·고유 아이템
- 설정 조건
- 계산의 공격·방어·회복·상세 설명
- 파티와 메모
- 오류·업데이트·확인 팝업

동적 값 때문에 같은 문장이 여러 형태로 기록되면 숫자와 식별자를 정규화한 뒤 하나의 서식 항목으로 관리한다.

### 5. 공개 패키지

최종 ZIP에는 실행에 필요한 바이너리, `Data`, `Fonts`, 라이선스와 사용자 문서만 포함한다. 다음 항목은 제외한다.

- `tools`
- `reports`
- `tests`
- `node_modules`
- 원본 공식 데이터 덤프
- `MalgunGothic-TestOnly.ttf`
- 캐시, 로그, 개인 설정과 빌드 파일

## 오류 처리 정책

- 공식 ID 충돌: 자동 적용 금지, 충돌 보고서에 기록
- 자리표시자·개행·색상 태그 불일치: 생성 실패
- 빈 공식 한국어: 자동 적용 금지
- 중국어 코드포인트 검출: 공개 검사 실패
- 의도하지 않은 영문 표시: 공개 검사 실패
- JSON 파싱 또는 중복 키 오류: 생성 실패
- 글꼴 미지원 글리프: 빌드 검사 실패
- 런타임 번역 누락: 공개 검사 실패
- 공식 데이터 버전과 로컬 클라이언트 버전 불일치: 생성 중단

## 테스트 전략

모든 동작 변경은 실패하는 검사부터 추가한다.

1. 기준 사전 키 집합, 메타데이터와 JSON 구문 검사
2. 공식 용어 출처와 우선순위 병합 검사
3. 자리표시자, printf 토큰, 개행과 색상 태그 보존 검사
4. 중국어·빈 값·미허용 원문 잔여 검사
5. 현재 화면 도달성 폐쇄 검사
6. 소스 자체 검사와 C++ 빌드
7. `--font-coverage-selftest`
8. 실행기 및 PoE1 엔진 스모크 테스트
9. 대표 공식 용어와 동적 능력치 렌더링 확인
10. 공개 ZIP 허용 목록 검사와 새 폴더 압축 해제 실행

자동 검사는 항목 수와 비율만 보고 성공시키지 않는다. 완료 판정은 미해결 사용자 표시 항목 0건, 중국어 잔여 0건, 손상된 서식 0건을 요구한다.

## 유지보수 경계

새 PoE 리그가 나오면 공식 데이터 버전을 올리고 같은 결합·폐쇄 검사를 다시 실행한다. 정상적인 업데이트는 전체 재번역이 아니라 다음 차이만 검수하게 한다.

- 새 공식 ID
- 공식 번역 변경
- 삭제된 ID
- 새 PoB UI 키
- 새 하드코딩 표시 문구
- 기존 규칙과 충돌한 동적 서식

범용 사용자용 생성기와 한국어 자동 업데이트 릴리스는 전체 한국어판이 안정화된 뒤 별도 작업으로 만든다.

## 수용 기준

- 원본 `PobTools-1.1.0`의 파일 해시가 작업 전과 같다.
- 한국어 사전과 소스 표시 경계에서 중국어가 0건이다.
- 현재 PoE1 사용자 표시 후보의 미해결 항목이 0건이다.
- 공식 용어 표본과 전체 출처 검사가 통과한다.
- 번역 서식 토큰 손상이 0건이다.
- 한국어 글꼴 자체 검사가 통과한다.
- 실행기와 PoE1 주요 화면이 오류 없이 실행된다.
- 공개 ZIP이 개발·개인 파일을 포함하지 않는다.
- 새로 압축 해제한 공개 ZIP에서 `Game=poe1`, `Locale=ko-KR`, `UpdateTranslations=0`으로 실행된다.
